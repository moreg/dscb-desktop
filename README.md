# 大神持笔 桌面版（ai-writer-desktop）

Electron 桌面应用：小说以**本地 Markdown 文件**存储，支持大纲 / 细纲 / 正文写作 / 记忆中心 / 去 AI 味 / 扫榜等。

当前数据布局为 **v4**（Markdown 单一真相源），兼容从 v3 `记忆系统/` 的一次性迁移。

## 开发

```bash
npm install
npm run dev      # 启动 Electron + Vite 热更新
npm test         # 单元测试
npm run build    # 构建产物到 out/
npx electron .   # 运行构建产物
```

## Web 版

同一套界面可以部署到服务器，用浏览器写作。数据在服务器磁盘上，登录口令由 `WEB_ACCESS_TOKEN` 指定。构建并启动：

```bash
npm run web
```

部署步骤、Docker 和反向代理见 [Web 部署](docs/Web部署.md)。

## 打包

```bash
npm run package      # 构建并打包成 Windows 安装包（release/*.exe）
```

产物：`release/dscb-desktop-setup-<version>-x64.exe`（NSIS 安装包）。发布与自动更新流程见 [GitHub 自动更新发布](docs/GitHub自动更新发布.md)。

0.1.30 将续写和正文调整的进度区分为上下文准备、等待正文首字和正文输出。前章长期核对与概要、结尾状态并行准备时，界面显示仍未完成的任务；此次进度修正不减少审核或改变记忆处理规则。

## 数据位置

- 项目库索引：`<userData>/library.json`
- 默认项目根：`<userData>/projects/<projectId>/`（可在设置中改）
- Windows `<userData>`：`%APPDATA%/ai-writer-desktop/`

## 架构

```
渲染进程 (React)  ──window.api──▶  IPC  ──▶  主进程 (Node)
                  contextBridge           ├─ ProjectService（项目信息 / library）
                                          ├─ ChapterService + ProseRepo（正文）
                                          ├─ MemoryService / MemoryEntityService
                                          │    └─ 记忆/*-repo + 追踪/伏笔
                                          ├─ OutlineService（大纲 / 细纲 + AI）
                                          ├─ WriteService / WriteFlowService
                                          ├─ DeslopService（去 AI 味）
                                          ├─ LlmService + SecretStore
                                          └─ 原子写 (.tmp + rename)
```

- `src/main/` — 主进程：窗口、IPC、文件 Repository / Service  
- `src/preload/` — contextBridge 暴露 `window.api`  
- `src/renderer/` — React UI  
- `src/shared/` — 共享类型  

记忆与追踪以 **Markdown 文件** 为单一真相源（`src/main/data/memory/*`、`skill-format/*`），不再依赖 `JsonCollectionRepository` 存业务实体。

记忆仓库复用带容量限制的文件内容、解析结果和实体索引缓存。每次查询仍校验文件元数据，新增、删除、重命名及外部编辑会刷新索引；不会用时间缓存绕过历史章节的来源校验。每类冷读取按最多 8 个文件一批并发执行，自动人物状态回写复用批次快照，并检查作者是否已修改卡片。记忆中心通过聚合统计接口获取计数，进入分类后才获取完整条目；内容未变化的同步不重复写入索引文件。

生成前的独立上下文读取并行执行，细纲只解析当前章与上一章，结尾状态提取与本地读取重叠，并复用同一份正文尾的进行中请求。正文召回复用经文件版本校验的磁盘索引解析结果，使用双字符倒排索引筛选后核对完整词组，以优先队列提取结果，保持原有排序、去重、字符预算与历史章节边界。目录清单会随文件监听和目录版本变化失效，并定期重新枚举；文件内容版本仍逐次校验。

## 正文自动去 AI 味

单章续写、重写和批量正文生成默认先扫描新稿并轻度去 AI 味，再复检并按现有设置进行概要与记忆处理。续写只处理新增片段；润色沿用项目题材、指定文风、当前去 AI 味设置和白名单。自动流程另用模型检查跨段流水账、证据清单、结果复述和交底对白；只有发现具体原文证据时才加入场景改写，改后仍检出问题则不自动采用。

自动写作的整场表达修订最多 2 次；返回已拒绝的同稿或连续两轮仍有相同核验问题时提前停止，保留原稿、待复核候选和具体原因。单章续写与批量写作都在同一章本轮内共享 3 次自动修复预算，事实核验不因预算耗尽而跳过。续写交稿时若还需局部修复衔接，修复后只复核事实，不再次进入整章润色；表达标记为待复核，可通过「精修正文」定向处理。

续写交稿的强制核对同时检查章节边界：读取本章及后续三章已有细纲（含散文禁区），核对本章允许推进的事件、揭示范围和停止位置；更远节点仍由总纲、卷纲约束。只有细纲、没有总纲也必须核对，结果缺少章节边界检查不能当作通过。强制核对或后续细纲对照发现超纲，都会尝试局部修复并独立复核；单次最多两轮，与正文生成、表达修订及伏笔补写共享整次续写的三次预算，写后检查不会重置额度。若同时遗漏伏笔，先修越界再补伏笔，最终仍须满足原细纲。检查针对最终正文，局部修复后重新验收；明确抢写、提前揭底会阻止交稿、记忆同步和批量推进，保留已生成稿供处理，不能靠自动回写细纲消除。合理场景扩写、猜测和铺垫不等于越界，作者明确调整计划时依其要求判断。生成或核对期间细纲变化会使旧结果失效；语义判断仍依赖模型与已提供的计划，不保证零漏检。

只有内容护栏通过、篇幅变化不超过 15%、没有待复核标记且没有残留问题的润色稿才自动采用；涉及文字表达改动时，还会对照原稿核验事实。核验返回格式异常会重新核验一次；发现具体事实差异时，最多自动定向修复两轮，每轮都以最初原稿为事实基线，复扫并重新核验。仍未通过则保留生成稿并显示具体原因；仅修正标点或空白时无需额外事实对照。后续检查、概要和记忆以最终正文为准。单章仍需手动保存，生成或自动润色期间停止会恢复本次开始前的正文。该流程不上传朱雀，也不承诺检测分数。

已用「一键写 10 章」生成的正文可在章节页点「批量去 AI 味」，选择已有章节范围与文风，一次处理最多 100 章；批量写作小结出现未采用的润色结果时，可点「批量重试去 AI 味」处理该批已完成章节。核验通过的稿件自动保存，未通过的章节保留已有正文并显示原因，不必逐章打开重写。旧章润色后仅更新该章概要，保留后续章节已经形成的人物状态和伏笔进展。

## 独立正文精修

编辑器工具栏的「精修正文」支持整章和选区；先在正文中选中文字，再点击即可只精修该范围。可选择表达、对白、节奏、场景或自定义目标。场景精修须先生成并确认方案，其余目标可直接生成候选。

精修不覆盖正文：候选稿、修改摘要和独立核验结果显示在可拖动的浮动面板中，可查看修改位置、完整前后对比及核验引文。每处改动可单独采用；核验未通过时也可以挑选单条，整章采用仍需核验通过。默认保留剧情事实、人物关系和章节结局，一次修订最多补救一次。需要改变剧情时使用「按要求重写」。

点击「采用并保存」或单条「采用此条」时检查编辑器原文、磁盘版本和参考上下文，变化后要求重新精修。采用前保存原文历史快照，采用后可「撤销本次精修」；若之后又改过正文，不会用撤销覆盖新修改。当前章节概要按正文指纹判定过期，不重放后续章节记忆。收起面板会保留任务和候选，离开章节会停止本页请求；重启后可重新打开查看候选。

自动生成候选默认关闭，可在精修面板按项目开启。它仅作用于本页完整单章写作结束后的未通过表达验收稿，已有通过结果的章节不会自动重复精修；自动候选仍需手动采用，不接入十章批量写作的等待链路。方案、候选、补救和独立核验走「精修正文」功能模型路由，未指定时使用当前默认 provider。候选与原文保存在项目 `.cache/chapter-refinement/`，按作品数据一起备份。

## 长篇脑洞生成

榜单任务按分类串行维护，列表读取与其他分类互不等待；市场资料与逐书开篇分析可重叠执行，榜单模型调用总并发保持为 2。前三章缓存逐次校验文件版本，内容未变化时复用快照与已验证分析。榜单脑洞保留已合格方案，只补生成缺失项，并排除重复书名与概念。长篇、短篇及榜单脑洞的流式文本按短批次发送和更新界面，完成、停止或离开工作区时处理剩余文本，草稿恢复与原文核验规则保持不变。

侧栏的「脑洞」是独立栏目，书案的「长篇脑洞」按钮也可进入。在这里按题材、可选方向、脑洞要求、预计章数和已有简介参考生成 3 个长篇方案，无需先建立作品或填写书名。题材、预计章数、简介参考与生成记录会在本机保存，离开栏目后可继续使用。

1. 填写创作条件并生成方案。每个方案包含故事设定、开篇钩子、长期主线、分卷推进、关键反转与终局走向；可换一批、收藏或复制，保留最近 5 批历史与最多 30 个收藏。
2. 点击「采用这个脑洞」打开预填书名、题材、章数和简介的新建项目弹窗，继续编辑后再点击「创建」。关闭弹窗可继续浏览脑洞，采用本身不创建作品。
3. 创建成功后，仅保存项目信息和脑洞简介，并将脑洞候选、历史与收藏复制到该作品。大纲、细纲及设定留待后续写作时添加。

停止或失败时保留已有方案与本次收到的文本，回到栏目后可查看恢复记录。长篇脑洞库与中短篇独立保存。已有项目仍可在「作品信息 → 脑洞生成」采用并保存为简介；后续使用细纲生成时，最新简介作为构思参考，遵循已有正式设定与大纲。

## 中短篇工作台

侧栏「书案 → 中短篇」提供独立作品列表与写作工作台：作品设定 → 全文大纲 → 分节正文 → 完结检查。短篇默认 8000 字 / 4 节，中篇默认 30000 字 / 12 节；全文目标和分节数可调整，分节预算的总和等于全文目标。

短篇新建表单与「作品设定」内提供「脑洞生成」：按题材、方向、写作要求和篇幅生成三个故事点子，包含开篇钩子、核心冲突、关键反转和结局；可换一批或停止，采用某个脑洞后填入故事梗概。新建时无需先填写作品名，已有作品的书名、大纲和正文由作者继续核对与修改。脑洞任务复用开局/大纲模型路由，不自动创建或保存作品。

新建表单支持按短篇/中篇分别恢复草稿。脑洞支持最近五批历史、三十个收藏、单个方案定向改写，以及通过完整标题和设定进行跨批去重；模型输出格式不完整时尽量提取有效方案，失败仍保留恢复文本。新建短篇的脑洞记录在创建成功后转入作品工作区。

大纲规划包含最终结局与伏笔回收，分节生成使用已有正文维持事实与衔接，末节按完结处理。三类任务分别复用「开局/大纲」「正文」「审稿」模型路由。生成结果先进入候选区，采用后可编辑并保存；停止或失败时保留原稿与已收到的候选。这个独立流程不自动运行章节页的去 AI 味和长篇记忆同步。

作品默认保存在 `<userData>/short-stories/<作品ID>/`，可在栏目顶部「选择文件夹」更改整个中短篇栏目的保存位置，重启后保留选择。切换时复制已有作品及历史快照，保留原文件；同编号内容冲突时保持原目录。配置与提交指针使用 JSON，正文、大纲和检查报告使用 Markdown。每次保存生成完整历史快照后原子提交，并校验版本和稿件指纹，避免其他窗口或外部编辑被旧稿覆盖。支持导出全文 Markdown、本地草稿恢复，以及保留草稿后重新读取已保存版本。操作说明见 [中短篇写作使用指南](docs/中短篇写作使用指南.md)。

## 一键同步

续写流程面板的「一键同步」默认更新记忆索引、对照细纲、提取记忆并生成章节概要；节奏评估和图解按需勾选。同步前须先保存正文，所有分析使用本次固定的正文快照；正文编辑或切章会取消旧分析流并丢弃旧结果。

重复点击时，本面板内已完成的分析在正文、项目依赖、规则和模型配置不变时直接复用，只补跑失败项。概要每次仍经过后端核对，有效概要可复用；无法确认模型身份的配置会重新分析。应用运行期间，写后记忆提取的最近结果在完整提示词、已知实体、生成参数和模型身份完全相同时也可复用。关闭面板后不保留面板的分析完成记录。

面板显示总耗时、各步骤耗时，以及「分析完成，待确认」「已保存」「复用有效分析」「失败，可补跑」。细纲、记忆和可选的节奏/图解仅生成候选；概要与索引保存到项目。应用候选时仍执行原有正文与证据校验。「重新分析全部」可强制重跑所选步骤。

## 一键写 10 章

章节页的「一键写 10 章」会预选下一段未写章节并开启连续模式；遇到已写章节时缩短默认范围。可修改章数，单批最多 100 章，已有正文不会被批量生成覆盖。

进度区每秒更新总耗时与逐章耗时，包含生成、润色、检查和限流等待；完成后停表，暂停期间不计时，继续或重试同一章时累计耗时。未结束批次的耗时随恢复记录保存在本机；旧批次没有历史计时数据时，从本次继续起统计。

连续模式以正文为准：每章生成并自动轻度去 AI 味后，先保存最终采用的正文，再做细纲对照，然后把所有差异（含漏写、P0、卷级变化）按正文回写本章细纲，并校准同卷后续未写章节的允许字段；细纲更新后重跑自检，最后按正文同步记忆/设定（不受自动记忆开关影响，自检/审稿结论不再整章拦下记忆，逐条证据校验照旧）。下一章对着更新后的细纲和记忆写，不会因为前一章偏离而连环报错。剩余的正文自检提示只记在逐章小结里；细纲缺失、回写或同步失败时暂停。

- **正文已保存、检查未完成**：继续时复用正文补跑检查，包括最后一章，避免重新生成。
- **正文生成或保存失败**：保留本批进度。生成完成但保存失败时，会尝试将恢复稿写入项目的 `.cache/batch-drafts/`，并在错误提示中给出路径。
- **停止与恢复**：停止会取消当前模型请求和后续校准；自动润色中途取消时，本章尚未正式保存，生成原稿保存在 `.cache/batch-drafts/` 供人工恢复，继续批量会重新生成本章。未结束的批次保留在本机，重新打开批量弹窗可继续。「结束本批」清除该批次的恢复记录。

### 批量验收、修复预算与恢复

批次显示“流程已完成”只表示执行结束。逐章小结另列“自动验收通过 / 表达待修订 / 检查仍有问题 / 验收未完成”。章节状态统一显示为“待写 / 正文 / 定稿”，原“草稿”和“润色”合并为“正文”；正文文件不存在或内容只有空白时仍显示“待写”。验收结果在逐章小结单独显示，事实与连续性冲突仍会暂停批次。

每章每轮后处理共享最多 3 次自动修复调用，包括场景、对白、事实、衔接、伏笔及清理补救；初次生成、正常润色遍次与独立核验不消耗这一预算。用完后保留当前稿，不能以预算耗尽为由跳过事实核验。用户明确重试会开始新一轮预算。

项目的 `.cache/chapter-stages/` 保存已验证的阶段结果，正文、计划、历史、文风、规则或模型配置变化后失效。仅身份明确的 HTTP 模型可跨轮复用；CLI/隐式模型或外部对标资料无法完整确定依赖时重新检查。长篇守门检查、提交前版本检查及记忆证据核验始终保留。

`.cache/chapter-runs/` 记录单章生成及后处理内各模型调用的耗时、调用是否成功和修复预算消耗，不记录提示词、模型回复或凭证。调用成功不等于正文验收通过；批次外层的概要补齐不计入这份记录。阶段记录含本地检查结果，应按作品数据对待。修改阶段提示词或验收协议时同步更新 `chapter-stage-cache.ts` 的缓存版本。

## 审稿系统

写作上下文包含独立的长期连续性核对：章节概要会额外记录道具的持有者、所有权、位置和消耗状态，按方向记录人物关系，并逐人记录已知、未知、怀疑或误信的秘密及信息来源。记录保存在项目的 `记忆/章节概要/`，附带正文指纹和原文依据；写作及 AI 深度审稿会检索本章之前的记录，不受近期 12 章摘要窗口限制。优先带入相关事项最近的有效记录，再补此前变化；正文改写或删除后不再引用该章旧记录。

旧项目无需迁移即可使用：未生成新格式记录的章节会通过历史正文专项检索补充，并在模型上下文中标明覆盖不足。在章节页点击「批量重新生成概要」，默认选择全书已有正文，可调整范围，也可勾选仅补齐缺失、过期或尚无连续性记录的概要。任务逐章调用模型并保存，失败后继续其他章节，支持停止及跳过已成功且正文未改的章节继续补齐；与批量续写/精修共用项目任务锁。全书补齐不受批量续写的 100 章限制。也可在单章流程面板点击「重新生成概要」。已有旧概要不会在后台自动触发模型调用；每章生成会产生模型用量。概要面板会显示道具、关系和知情记录，悬停可查看引文。新增召回使用本地索引，不额外调用模型；生成概要可能因提取更多记录增加输出用量。证据和预算有限时仍可能遗漏，审稿不会把未命中当成“从未发生”。

按「正文审核」技能集成，分两层，可在「设置 → 审稿规则」配置：

- **算法层**（实时、纯函数）：`src/main/data/chapter-audit.ts`
- **LLM 层**（按需、流式）：`src/main/data/review-flow-service.ts`

检查项注册表：`src/main/data/skill-prompts/review-checks.ts`。自定义检查引擎：`custom-check-engine.ts`。

## 正文保真与分段规则（2026-10-24）

新写内容默认以一句一段为主，段间空一行，必要时自然合段；续写的新段落接缝也空一行。已全绿正文保持原样，不因规则更新重排。正文格式化保留语意段落、台词句号、合法省略号和破折号，以及动作原有顺序。对白比例按场景安排，不再默认要求 70%。仅建议级扫描结果不阻断已通过事实核验的润色，建议仍保留在报告中；事实差异和阻断问题继续保留原稿。

对话默认也以一句一段为主，中间有句号时优先按语意拆成独立对话段，每段引号完整，段间空一行，必要时自然合段。拆段保留说话人、问答关系与原有动作顺序，不添加动作或重复标签，不把句号一律改成逗号。该规则用于新写内容与明确授权的改写，格式化器不按句号机械切开已有正文。

规则源为 `src/shared/prose-policy.json`，版本为 `2026-10-26.1`。运行 `node scripts/sync-prose-policy.mjs` 将共享规则同步到相邻技能目录和本地 `.agents/skills`；运行 `node scripts/sync-prose-policy.mjs --check` 检查 33 份副本。非默认技能路径可传 `--skills=绝对路径`。仅迁移逐字相同的历史内置条款，保留作者自定义规则和设置文件原文。
