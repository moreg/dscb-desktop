# 大神持笔 桌面版（ai-writer-desktop）

Electron 桌面应用：小说以**本地 Markdown 文件**存储，支持大纲 / 细纲 / 正文写作 / 记忆中心 / 去 AI 味 / 扫榜等。

当前数据布局为 **v4**（Markdown 单一真相源），兼容从 v3 `记忆系统/` 的一次性迁移。

## 开发

```bash
npm install
npm run dev      # 启动 Electron + Vite 热更新
npm test         # 单元测试
npm run build    # 构建产物到 out/
npx electron .   # 运行构建产物
```

## 打包

```bash
npm run package      # 构建并打包成 Windows 安装包（release/*.exe）
```

产物：`release/dscb-desktop-setup-<version>-x64.exe`（NSIS 安装包）。发布与自动更新流程见 [GitHub 自动更新发布](docs/GitHub自动更新发布.md)。

## 数据位置

- 项目库索引：`<userData>/library.json`
- 默认项目根：`<userData>/projects/<projectId>/`（可在设置中改）
- Windows `<userData>`：`%APPDATA%/ai-writer-desktop/`

### 项目目录（v4）

新建长篇项目只保存 `project.json` 中的项目信息与简介。采用脑洞并确认创建项目后，完整创意会保存为简介；大纲、细纲和设定可等开始写作时再添加。下面展示完整写作项目可使用的目录结构。

## 架构

```
渲染进程 (React)  ──window.api──▶  IPC  ──▶  主进程 (Node)
                  contextBridge           ├─ ProjectService（项目信息 / library）
                                          ├─ ChapterService + ProseRepo（正文）
                                          ├─ MemoryService / MemoryEntityService
                                          │    └─ 记忆/*-repo + 追踪/伏笔
                                          ├─ OutlineService（大纲 / 细纲 + AI）
                                          ├─ WriteService / WriteFlowService
                                          ├─ DeslopService（去 AI 味）
                                          ├─ LlmService + SecretStore
                                          └─ 原子写 (.tmp + rename)
```

- `src/main/` — 主进程：窗口、IPC、文件 Repository / Service  
- `src/preload/` — contextBridge 暴露 `window.api`  
- `src/renderer/` — React UI  
- `src/shared/` — 共享类型  

记忆与追踪以 **Markdown 文件** 为单一真相源（`src/main/data/memory/*`、`skill-format/*`），不再依赖 `JsonCollectionRepository` 存业务实体。

## 正文自动去 AI 味

单章续写、重写和批量正文生成默认先扫描新稿并轻度去 AI 味，再复检并按现有设置进行概要与记忆处理。续写只处理新增片段；润色沿用项目题材、指定文风、当前去 AI 味设置和白名单，有命中问题才调用改写模型。

只有内容护栏通过、篇幅变化不超过 15%、没有待复核标记且没有残留问题的润色稿才自动采用；涉及文字表达改动时，还会对照原稿核验事实。核验返回格式异常会重新核验一次；发现具体事实差异时，最多自动定向修复两轮，每轮都以最初原稿为事实基线，复扫并重新核验。仍未通过则保留生成稿并显示具体原因；仅修正标点或空白时无需额外事实对照。后续检查、概要和记忆以最终正文为准。单章仍需手动保存，生成或自动润色期间停止会恢复本次开始前的正文。该流程不上传朱雀，也不承诺检测分数。

已用「一键写 10 章」生成的正文可在章节页点「批量去 AI 味」，选择已有章节范围与文风，一次处理最多 100 章；批量写作小结出现未采用的润色结果时，可点「批量重试去 AI 味」处理该批已完成章节。核验通过的稿件自动保存，未通过的章节保留已有正文并显示原因，不必逐章打开重写。旧章润色后仅更新该章概要，保留后续章节已经形成的人物状态和伏笔进展。

## 长篇脑洞生成

侧栏的「脑洞」是独立栏目，书案的「长篇脑洞」按钮也可进入。在这里按题材、可选方向、脑洞要求、预计章数和已有简介参考生成 3 个长篇方案，无需先建立作品或填写书名。题材、预计章数、简介参考与生成记录会在本机保存，离开栏目后可继续使用。

1. 填写创作条件并生成方案。每个方案包含故事设定、开篇钩子、长期主线、分卷推进、关键反转与终局走向；可换一批、收藏或复制，保留最近 5 批历史与最多 30 个收藏。
2. 点击「采用这个脑洞」打开预填书名、题材、章数和简介的新建项目弹窗，继续编辑后再点击「创建」。关闭弹窗可继续浏览脑洞，采用本身不创建作品。
3. 创建成功后，仅保存项目信息和脑洞简介，并将脑洞候选、历史与收藏复制到该作品。大纲、细纲及设定留待后续写作时添加。

停止或失败时保留已有方案与本次收到的文本，回到栏目后可查看恢复记录。长篇脑洞库与中短篇独立保存。已有项目仍可在「作品信息 → 脑洞生成」采用并保存为简介；后续使用细纲生成时，最新简介作为构思参考，遵循已有正式设定与大纲。

## 中短篇工作台

侧栏「书案 → 中短篇」提供独立作品列表与写作工作台：作品设定 → 全文大纲 → 分节正文 → 完结检查。短篇默认 8000 字 / 4 节，中篇默认 30000 字 / 12 节；全文目标和分节数可调整，分节预算的总和等于全文目标。

短篇新建表单与「作品设定」内提供「脑洞生成」：按题材、方向、写作要求和篇幅生成三个故事点子，包含开篇钩子、核心冲突、关键反转和结局；可换一批或停止，采用某个脑洞后填入故事梗概。新建时无需先填写作品名，已有作品的书名、大纲和正文由作者继续核对与修改。脑洞任务复用开局/大纲模型路由，不自动创建或保存作品。

新建表单支持按短篇/中篇分别恢复草稿。脑洞支持最近五批历史、三十个收藏、单个方案定向改写，以及通过完整标题和设定进行跨批去重；模型输出格式不完整时尽量提取有效方案，失败仍保留恢复文本。新建短篇的脑洞记录在创建成功后转入作品工作区。

大纲规划包含最终结局与伏笔回收，分节生成使用已有正文维持事实与衔接，末节按完结处理。三类任务分别复用「开局/大纲」「正文」「审稿」模型路由。生成结果先进入候选区，采用后可编辑并保存；停止或失败时保留原稿与已收到的候选。这个独立流程不自动运行章节页的去 AI 味和长篇记忆同步。

作品默认保存在 `<userData>/short-stories/<作品ID>/`，可在栏目顶部「选择文件夹」更改整个中短篇栏目的保存位置，重启后保留选择。切换时复制已有作品及历史快照，保留原文件；同编号内容冲突时保持原目录。配置与提交指针使用 JSON，正文、大纲和检查报告使用 Markdown。每次保存生成完整历史快照后原子提交，并校验版本和稿件指纹，避免其他窗口或外部编辑被旧稿覆盖。支持导出全文 Markdown、本地草稿恢复，以及保留草稿后重新读取已保存版本。操作说明见 [中短篇写作使用指南](docs/中短篇写作使用指南.md)。

## 一键写 10 章

章节页的「一键写 10 章」会预选下一段未写章节并开启连续模式；遇到已写章节时缩短默认范围。可修改章数，单批最多 100 章，已有正文不会被批量生成覆盖。

连续模式以正文为准：每章生成并自动轻度去 AI 味后，先保存最终采用的正文，再做细纲对照，然后把所有差异（含漏写、P0、卷级变化）按正文回写本章细纲，并校准同卷后续未写章节的允许字段；细纲更新后重跑自检，最后按正文同步记忆/设定（不受自动记忆开关影响，自检/审稿结论不再整章拦下记忆，逐条证据校验照旧）。下一章对着更新后的细纲和记忆写，不会因为前一章偏离而连环报错。剩余的正文自检提示只记在逐章小结里；细纲缺失、回写或同步失败时暂停。

- **正文已保存、检查未完成**：继续时复用正文补跑检查，包括最后一章，避免重新生成。
- **正文生成或保存失败**：保留本批进度。生成完成但保存失败时，会尝试将恢复稿写入项目的 `.cache/batch-drafts/`，并在错误提示中给出路径。
- **停止与恢复**：停止会取消当前模型请求和后续校准；自动润色中途取消时，本章尚未正式保存，生成原稿保存在 `.cache/batch-drafts/` 供人工恢复，继续批量会重新生成本章。未结束的批次保留在本机，重新打开批量弹窗可继续。「结束本批」清除该批次的恢复记录。

## 审稿系统

按「正文审核」技能集成，分两层，可在「设置 → 审稿规则」配置：

- **算法层**（实时、纯函数）：`src/main/data/chapter-audit.ts`
- **LLM 层**（按需、流式）：`src/main/data/review-flow-service.ts`

检查项注册表：`src/main/data/skill-prompts/review-checks.ts`。自定义检查引擎：`custom-check-engine.ts`。
