# 桌面版榜单脑洞：生成与复核

当前提示词版本为 `chart-ideas-v16-action-and-demand`。规则集中在 `src/main/data/fanqie-chart/fusion-rules.ts`，生成提示词和独立复核共享同一套规则。实际调用、格式校验和正式保存由 `service.ts` 与 `fusion-review.ts` 承接。

每条至少提取两本榜单书中有简介原文支持的具体梗，整批分别比较来源机制和开场冲突。展开覆盖世界、能力、配角、实际目标、读者回报与长篇阶段推进，并与前三章相互核对。

## v15 新增检查

- 删除合法性：关闭来源今后的核心操作，保留既得成果、新增能力以及它们原有的触发条件。只取消限制却继续保留核心能力的反事实无效；失败报告也不能使用这种论据。
- 执行条件：区分设备、使用场域、启动操作、耗材与获得设备的渠道。需要新信息不等于需要新设备；设备来自现代也不等于只能在现代使用。缺少条件时不能擅自判可行或必需。
- 目标与材料：本地持续供粮要尝试购种后自繁，不能只排除一次性购粮。复原灭绝物种、保留完整活母本及连续谱系等独特成果则不能降格为普通种粮。
- 组合替代：每个阶段在交流、人工取物、既有队伍三类路线之外，另做一次最强合理组合。保留旧库存、收入、土地、设备、团队、其他能力和预警提前量，比较具体步骤、期限、数量与同一回报。

## 结构化复核

v16 增加以下检查，并保留 v15 的所有删除和组合替代规则。

- `action_checks`：开篇、中段、后段各自核对观察者位置、信息取得与送达、决策和执行顺序。核验依赖尚未完成的迁移时报告 `action_loop_gap`，不能靠现成设备名称假定跨界信号或个人通道。
- `deletion_audit.dependency_boundary/input_dependency/branch_analysis`：分清来源检测输入与新增处理功能。边界模糊时按两种合理解释分别推演，登记未证实，不能选一支冒充事实；合法条件分支不同于审稿人擅改能力。
- `stage_goals.new_requirement/old_stock_test/need_established`：新功能、数量、时限的缺口必须明确，成熟品、旧库存和允许延期必须保留。不能仅因换了批次就认定新增需求成立，也不能削弱真正独特回报。
- `chapter_comparisons`：对全部方案对引用各自三章原文，比较整条具体因果推进。仅首幕不同、二三章仍套拒绝过劳和结账模板时报告 `chapter_progression_repeat`；抽象的成功、代价、成长并不自动构成重复。

行动闭环、新需求或检测输入边界未证实时，不能把对应阶段来源判为必需。章节证据必须来自对应章节单一字段，不能拼接字段伪造引文。用户保留方案仍参与整批审查，但不被重写。

每个阶段先固定 `stage_goals`，不同来源的删除检验必须共用同一目标。目标增加 `material_substitution_test`；每个来源增加 `deletion_audit`；每个阶段增加 `execution_audit` 和 `combination_check`。

校验器检查字段完整性、阶段/来源/方案对覆盖、引文与原稿逐字匹配及结论一致性。删除审计不合法时整份报告无效；执行条件不明或任何单项、组合替代可行/未排除时，不能判该阶段来源必需。协议合格仅说明报告可审计，不等于模型的因果判断必然正确，仍需核查它是否误读原文。

生产流程只保存通过校验及内容复核的完整结果；复核异常、取消或拒收不覆盖已有脑洞。提示词调整不自动重写历史数据。

## 手动真实模型验证

`scripts/run-fanqie-fusion-live.mjs` 调用桌面版实际提示词、模型服务与解析器，将全批原稿和两轮复核保存到独立 scratch 目录，未通过项不进入正式库。配置、榜单日期、提示词版本、通道、超时覆盖及完整请求输出均需记录。

`FUSION_LIVE_HISTORY_FILE` 可提供前一批已生成方案作为避重参考；`FUSION_LIVE_GENERATION_FILE` 是审稿重放功能，使用时不能声称重新生成了脑洞。`FUSION_LIVE_TIMEOUT_MS` 只影响测试 bundle，不更改桌面版默认超时。

`FUSION_LIVE_RETAIN_FILE` 接受用户要求保留的方案数组。模型只补足到三条，原始新回复另存 `generated-candidates.json`，合并后的全批存 `raw-candidates.json`。保留内容前后计算哈希，变化即停止；普通终审与融梗复核均覆盖合并全批。

`scripts/render-fanqie-fusion-live.mjs` 展示全部原始字段并检查原始字符串无遗漏。展示原稿时，应将模型自称的删除检验与最终核查结论明确分开。
