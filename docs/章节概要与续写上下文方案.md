# 章节概要与续写上下文方案

## 读取层级

1. 本章已有正文：完整原文，保留未完成句子、台词与剧情进度。
2. 上一章：完整原文；结尾状态仍从最后 1500 字符提取。上一章不重复注入概要。
3. 更早最近 12 个已写章节：优先读取与当前正文哈希一致的章节概要；没有有效概要时沿用原有的、有来源的剧情点摘要或正文摘录。
4. 远期章节：通过正文检索命中时，最多补入 4 章有效概要，同时保留命中的原文证据。
5. 本章细纲、人物状态、设定和伏笔：仍按原有规则提供，概要只陈述实际发生的事，不取代写作约束。

本章或上一章正文超过 4 万字符时显式报错，不截掉中段后继续写。

## 生成与存储

- 每章存于 `记忆/章节概要/第NNN章.json`，带章节号、正文哈希、生成时间、关键事件、状态变化和未结事项。
- 每个条目都带正文原句作为证据。证据找不到、结构不完整或概要过长时拒绝写入；旧文件保留，但正文哈希不匹配时不可用于续写。
- 仅在完整结果校验通过后原子覆盖。相同正文哈希的自动任务直接复用；手动「重新生成概要」强制更新。
- 生成过程中如正文文件改变或更晚的概要任务开始，旧结果不落盘。

## 入口与失败处理

- 续写流程面板展示概要、过期状态和「生成概要／重新生成概要」按钮。
- 「一键同步」在现有步骤之后生成或更新概要。写后自动同步启用时也生成概要；`full` 流程复用同一正文哈希的结果。
- 「一键十章」在每章保存及写后检查后生成概要，再进入下一章。生成失败则暂停在当前章；继续时复用已保存正文，补跑后处理和概要，不重新生成正文。
- 正文一经修改，旧概要立即显示为过期；续写读取时再次核对磁盘正文哈希，失效概要不会成为既成事实。
