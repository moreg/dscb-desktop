# 300万字长篇：续写与一键10章

当前补强面向逐章、分批推进千章级长篇。存储与检索使用本地正文和章节概要；语义核对使用辅助模型。它能减少长期遗忘、人物突然知道秘密及主线偏移，不代表已经完成300万字真实小说的自动成稿质量验证。

## 写作与交稿

- 写前读取作者的全书主线、当前卷范围、大纲内嵌本卷计划及独立卷纲。主线资料来自大纲，不用当前正文或自动回写后的细纲重新定义目标。
- 普通续写在润色后交稿前核对主线、逐人知情与长期剧情线。已有原稿保留在原有保存/恢复流程中，冲突不会作为成功交稿继续推进。
- 一键多章在按正文回写细纲之前再次核对；恢复已保存章节也经过此入口。明确冲突、核对失败及取消都会暂停，不能靠回写细纲把偏移变成正确。
- 核对同时读取前12章带有效正文依据的实际进展，帮助识别逐章累积的目标替换；不会因几章没有提到主线就机械判定跑偏。
- 写后同步提交记忆之前也核对；明确冲突返回待核对状态，未完成返回失败。存在待处理问题的批次不生成本章概要，避免把未通过的稿件写入后续长期台账。
- 冲突信息包含本章原句和对应计划/历史依据。作者可修正文，或明确调整作者计划，再补跑当前章检查。单章临时要求经 IPC 传入写后核对，补跑复用绑定同一稿件的上下文。
- 核对不依赖“自动深度审稿”开关，使用辅助模型路由。会增加模型调用与等待；相同全文、计划、历史及可识别模型的成功结果可复用5分钟。模型身份不可确认时不复用，失败与取消不缓存。

## 长期记忆与人物知情

- 原有道具、关系和人物认知台账增加 `thread` 类型，保存实际承诺、目标、部分兑现、完成、放弃及被推翻的变化。每条均绑定章节正文哈希和可定位原文。
- 写后概要提取使用相关旧台账作为命名参考，要求沿用同一秘密主题和任务名称，只记录本章实际变化，不能复制历史状态作为新事实。
- 本章人物知情边界拥有2400字符独立预算；按人物轮流保留记录，避免主角的大量记录挤掉其他视角。无记录标为未知，不推定已知或不知。
- 已确认且无歧义的别名用于归一认知/关系主体；同一事项以较晚记录优先，保留上次变化依据。相同任务也会扩展读取后续完成记录，避免只找回早期承诺。
- 认知必须区分已知、不知、怀疑、误信及信息来源。旁白、读者或同伴知道不等于角色知道；缺少记录本身不会被模型当作矛盾证据。
- 热查询复用已验证的章节事实，正文哈希或概要文件指纹变化时逐章失效。缓存有条数和内存上限，重新打开应用可从正文与概要重建。回写旧章仍排除未来记录。

## 既有项目

旧概要与旧项目继续可读。缺失的台账不会自动补造；旧书如需完整的长期任务和知情记录，可在章节概要功能中对已写范围重新生成概要（已有但缺少新任务记录的概要需选择重建，而非仅补缺）。写前应有明确全书主线和当前卷目标；没有计划或历史证据时，系统不能凭空保证主线一致。

全书主线与当前卷完整计划合计超过18000字符会明确要求整理；全章超过40000字符不作完整核对。两者都不静默截掉中段或尾部再声称通过。预算未覆盖的历史仍标注覆盖不足。

## 验证范围

- 新增1000章、合计300万字符的磁盘样例，验证远章认知反转、承诺兑现、旧章时间边界、概要编辑及正文改写后的失效；热查询不重读全部正文。该样例是检索与缓存验证，内容不是300万字真实小说。
- 模拟模型验证普通续写冲突保稿、批次停止且不生成下一章、回写细纲之前拦截、恢复重检、记忆提交拦截、检查中作者改计划、无效JSON/失败/取消不冒充通过。
- 语义结论仍依赖模型及已召回的证据。当前没有新增嵌入向量检索，也未证明所有跨章因果和缓慢主线偏移都能检出；每卷仍需审阅实际成稿和阶段目标。

## 二次复查：检查入口与记忆隔离

- 新生成原稿在保存之前登记持久待核对状态，润色中断、长篇核对失败或应用退出后仍保留。状态位于 `追踪/.longform-review.json`，不随 `.cache` 或批次任务记录清理。
- 长篇核对与批次写后流程分别登记。某章通过一次长篇核对、手动生成概要或同步部分记忆，都不能解除该章尚未完成的批次写后检查。批次在全部步骤和概要完成、保存稿版本仍匹配后才解除隔离。
- 待核对章节同时从原文检索、近期概要与连续性台账中排除；前章仍有待核对正文时，后章生成会明确停止。正文仍可查看、修改、重试，不删除作者稿件。
- 恢复时核验实际正文，不能仅信任前端 `completed`、`pendingPostProcessChapter` 或缓存 `proseSynced`。全部完成快捷入口、关闭连续模式、关闭自动记忆同步、恢复保存稿以及按要求重写均经过核对；未完成检查不再误报整批完成。
- 单独生成概要、概要批量重建、写前自动补齐和原文引句降级分支也受核对约束。重新生成概要不会把未通过稿件洗成历史事实；缓存概要还须具有与原文相符的引句。
- 强制确认候选条目不能绕开整章长篇冲突；按章节一键采纳新增实体须核对候选正文哈希、整章问题与长篇结论，单独从正文应用设定补丁也经过核对。
- 记忆提取或细纲联动期间，正文、历史来源或作者计划改变时，在提交前再次核验；旧稿候选不能依赖等待前的通过结论入库。
- 作者明确给出的临时要求在核对通过后，与保存稿及当时的主线计划哈希一起保存于 `追踪/.longform-context/`。重启或补概要可沿用相同稿件、相同计划下的授权；改稿或改计划后不继续覆盖新计划。
- 状态文件损坏或被截为空文件会明确失败，不按“没有待核对章节”放行。旧任务也不能解除较新任务的隔离状态。

新增专项回归覆盖热索引隔离、重启后继续写、关闭同步、全部完成快捷入口、恢复稿与缓存标记、提取等待期间改前章、润色中断、重写、概要重建、候选强制写入及作者临时要求的版本边界。仍使用模拟模型验证流程行为，不代替真实小说成稿审阅。

## 真实模型集成测试

手动执行 `npm run test:longform:live`，通过应用本身的 `SecretStore` 和 `LlmService` 读取现有路由并调用真实模型。普通 `npm test` 不调用外部模型。默认读取桌面版用户目录，可用 `LONGFORM_USER_DATA` 指定其他桌面数据目录。

测试数据与逐次提示词、原始模型输出、路由元数据和 JSON 报告保存在独立的 `scratch/longform-live/run-*`，不写入作者书库，不导出密钥。700章背景是明确标记的合成磁盘样本，早期/后期知情台账由真实模型提取，第701章由真实模型生成；不把样本规模说成700章真实生成小说。此轮聚焦长篇核对及批次恢复，自动润色服务未启用。

恢复专项可复用首轮隔离数据：设置 `LONGFORM_LIVE_FIXTURE` 为首轮结果目录，再执行同一命令。它重新提取第640章，测试隐蔽对白泄密、知情者故意撒谎和错误稿概要隔离，再在真实批次记忆提取之后主动取消，重建服务补跑保存稿，核实无重复生成及检查点清除。`LONGFORM_LIVE_DIR` 可指定本次报告目录；测试专用的 `LONGFORM_LIVE_CHAPTER_PROVIDER=active` 可将正文路由临时指向当前默认模型，路由覆盖仅存在测试进程内，写入报告但不改用户配置。

同样指定隔离项目后，`LONGFORM_LIVE_CONTINUATION_ONLY=1` 单独测试从真实生成稿的半章继续写，核验旧稿保留和不重复拼接；`LONGFORM_LIVE_MEMORY_PRESSURE_ONLY=1` 单独加入1396条带正文依据的同角色认知干扰，再用真实模型检查正确稿和泄密稿。这些专项会改写隔离测试项目，应各自使用副本，并更新副本 `library.json` 中的项目绝对路径。脚本拒绝操作隔离目录外的项目。背景和干扰状态均为合成测试数据，关键状态来自真实模型提取。

真实提取发现“概要写了某人仍不知情，却遗漏对应 knowledge 台账”的情况。已要求显式重申的不知/误信状态也逐人记入台账，并交叉核对概要中的有名主体认知事实与台账证据；缺失时重提，不自行推断补写。普通概要复用、自动补齐和批量仅补缺入口也校验该覆盖条件。该检查是有限的可定位覆盖校验，不能证明所有正文语义都提取完整。

已确认的知情漏项重提仍未修复时，返回 `MEMORY_KNOWLEDGE_INCOMPLETE`，不能通过原文引句降级为看似完整的空台账；自动补齐亦保留该失败。具体场景、实测范围与产物见 [2026-10-20真实模型测试报告](长篇真实模型测试-2026-10-20.md)。
