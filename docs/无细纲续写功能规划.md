# 无细纲续写功能规划。

规划日期：2026-11-13。

核心功能已于 2026-11-13 实施，以下保留产品规则与验收依据，实际覆盖和限制见文末。

## 一、目标与约束。

当用户要续写的目标章节没有有效细纲时，先根据全书大纲及可用的前文、记忆生成五个不同的写作方向，其中明确推荐一个。单章由用户选择或调整后生成正文；“一键十章”自动采用推荐方向。章节完成后，根据最终正文生成本章细纲，并完成概要及记忆同步。上一章正文、历史细纲和记忆均可缺失，只有大纲时也必须支持这条完整流程。

“没有下一章细纲”以实际写作的目标章号为准，例如在第十章后写第十一章，应检查第十一章细纲；同章已有半稿时，检查该章细纲，并承接该章已写内容。

新增共同约束：用户没有明确要求全书完结时，续写不得生成全书完结内容。该约束同时适用于有细纲续写和无细纲续写，覆盖方向生成、正文生成与交稿核验。

## 二、现有实现与需要补齐的环节。

本节记录实施前的代码情况，所列核心环节已完成接入。

- `src/renderer/src/ChapterEditor.tsx` 已有续写入口、临时要求和写后流程展示，可接入方向选择界面。
- `src/main/data/write-service.ts` 的单章流程允许缺纲生成，但没有五个方向及用户选择环节；批量流程现有的写前自动补纲需要改为缺纲时生成方向并采用推荐项，正式细纲改在正文完成后反向生成。
- 当前正文上下文主要注入总纲摘要及所在卷纲。新流程应增加完整总纲读取，保留全书目标、阶段进展、关键揭示与后续安排。
- 新流程需要允许上一章正文缺失，包括项目只有大纲、没有任何正文和细纲的情况；现有前章状态恢复与检查不得因此强制补写上一章，或将计划伪造为已发生事实。
- 现有细纲差异同步主要处理已有细纲；完整同步流程会核验本章细纲，缺纲时需要先补建。
- `DetailedOutlineWriter.update` 只更新已有章节，需要补充符合现有格式的逐章细纲创建能力。
- 现有概要、记忆证据检查、版本校验、取消和同步重试机制应继续复用。

## 三、用户操作流程。

1. 用户点击“续写”，后端判断目标章节是否有可执行的细纲。只有章名、章号或空模板，不视为有效细纲。
2. 有有效细纲时沿用常规续写；没有时进入“选择本章走向”，读取大纲和实际可用的资料。没有上一章正文不阻断，也不要求先生成上一章或细纲。
3. 系统一次返回恰好五个方向，每个方向展示名称、承接点、主要冲突与推进、本章落点、章末悬念和符合大纲的理由。其中恰好一个标记“推荐”，并给出推荐理由。有上一章正文时说明如何承接实际结尾；只有大纲时说明如何落实当前阶段，并标注“依据大纲规划”。
4. 单章界面默认选中推荐方向，用户仍可改选、编辑内容、补充临时要求，或点击“重新生成五个方向”；重新生成时保留作者已输入的要求。
5. 用户点击“按此方向续写”，沿用模型、文风、目标字数、正文规则和去 AI 味设置。
6. 章节完成后依次显示“正文已保存 → 正在生成本章细纲 → 正在生成概要及同步记忆 → 本章处理完成”。

单章“下次直接续写”的偏好不能跳过缺纲时的方向选择。“一键十章”则按用户明确指定的自动推荐规则执行，无须逐章确认。生成候选方向不会创建正式细纲，也不会改动剧情记忆。

### 一键十章的逐章流程。

1. 对当前待写章节检查有效细纲，已有细纲时按该细纲写作，不用推荐方向覆盖作者的既定安排。
2. 缺少细纲时，基于此刻的大纲、最新正文及已同步记忆，生成五个方向和唯一推荐项，自动采用推荐方向。
3. 完成本章正文生成、检查与保存；本次缺纲章依据最终正文创建细纲，已有细纲章沿用现有差异核验与同步机制，随后完成概要及记忆同步。
4. 本章必要步骤全部成功后，重新读取上下文，再处理下一章，直到完成本次十章任务。

不在批次开始时一次选定十章方向。每章推荐都依据前章最终实际结果动态生成，避免沿用已偏离正文的旧计划。

批量进度显示当前章的推荐方向名称、推荐理由与处理阶段；已完成章节保留五个候选及采用记录，方便回看。

推荐结果无效、正文检查失败、细纲生成失败或记忆未同步完成时，保留当前结果并暂停，不带着未处理问题进入下一章。继续任务时复用有效的已选方向与已保存正文，补跑失败步骤；上下文改变时重新核对，不能重复生成或覆盖已交付正文。

## 四、五个方向的生成依据。

上下文分为已发生事实、待核对资料和未来计划，明确标注，不把大纲里的未来事件写成历史。上一章正文和细纲是可选输入，大纲是本功能的核心规划依据。

- 已发生事实：实际存在的上一章完整正文、本章已有正文、与来源版本一致的概要，以及有可核查证据或作者明确确认的人物、物品、时间线、知情状态和伏笔记忆。只有读到相应原文时，才提取其结尾状态。
- 待核对资料：来源正文缺失、无法核对版本的旧概要或旧记忆，可作为线索参考，不能冒充已验证事实。
- 未来计划：完整总纲、实际存在的相关卷纲、当前阶段目标、逐章节奏，以及已有的相邻章细纲与禁止提前兑现的关键事件；缺少细纲时直接依据大纲规划。
- 作者约束：作品设定、长期写作要求、本次临时要求和是否明确授权全书完结。

五个方向必须在行动选择、核心冲突、阻力或信息揭示上有实际区别，不能只换标题或措辞；方向应推动同一作品的既定主线，并说明与可用前文或大纲阶段的关系。

推荐依据为前文衔接、主线推进、人物动机、当前节奏、伏笔时机及后续可持续性。推荐理由须联系本书实际内容，不能只写“更精彩”等空泛结论；推荐项同样必须满足事实、章节边界和禁止主动完结等约束。

模型一次返回五个带独立标识的方向、唯一推荐方向标识及推荐理由。后端校验恰好五项、标识唯一、推荐标识确实属于候选集合；格式错误或推荐项不合规时重新生成，仍失败则明确报错，不用数组第一项代替推荐。

按实际资料自动选择生成方式，不额外要求用户确认“降级模式”。

| 可用资料。 | 生成方式。 |
| --- | --- |
| 大纲、上一章正文均存在，目标章无细纲。 | 结合上一章实际结尾与大纲阶段生成五个方向。 |
| 有大纲，没有上一章正文，但有更早正文或有效记忆。 | 结合已确认事实与大纲定位当前阶段，未知的上一章细节保持未知。 |
| 只有大纲，没有正文、细纲或记忆。 | 根据目标章号、大纲中的阶段安排及作者要求，直接规划五个方向，选择后写目标章，不补造此前章节的经历。 |
| 第一章，无上一章正文。 | 根据大纲的开篇目标生成五个开篇方向，正常完成写后细纲和记忆同步。 |

只有大纲且阶段定位不明确时，五个方向中明确展示各自的切入场景及阶段假设，用户选择即采用该写作起点，不需要先补细纲。章号仅帮助定位计划，不能证明前面的事件已经发生。

候选方向必须遵守人物能力和知情边界，不凭空补造前情，不提前兑现后章核心事件，不把用户未选择的方向混入正文。

完整大纲通常直接读取；超出模型上下文预算时，分段提炼并保留所有阶段目标、关键转折、结局约束及当前进度，不以截取大纲开头代替全书视野。必要信息仍无法完整提交时，明确提示，停止生成。

界面简要说明实际采用的资料，例如“未找到上一章正文，本次依据全书大纲规划”。不得假称读过不存在的前文，也不以资料提示阻断正常选择和写作。总纲也缺失时才属于另一种资料不足场景，本方案不自动将其视为“只有大纲”模式。

## 五、禁止主动完结的规则。

默认不允许全书完结。大纲结局、最后一章标号、预定总章数、模型判断“故事该结束了”，均不构成用户授权。

“一键十章”只授权连续写作及自动采用推荐方向，不授权全书完结；本批次第十章也不得因为任务结束而写成全书终局。推荐算法与每章交稿检查均执行这一规则。

仅用户明确提出本次要写全书完结、最终章等要求，才允许本次生成进入全书收束。结束本章、结束一场战斗、解决当前事件、收束本卷，均不等于允许全书完结。

未获授权时，五个方向不得包含全书终局、终章、尾声、人物一生归宿或全面封闭后续空间的安排。可以兑现本章或阶段成果，但应保留与主线一致的后续推进空间。

正文生成提示与交稿检查同时执行这一要求。检查应判断剧情是否进入全书终局，不能只检查“全书完”等词；人物台词中的“结束了”等普通表达不应误报。

若全书大纲已经走到终局但用户未授权完结，应在既定世界观内提出合理的非完结推进；确实没有可行空间时说明冲突，让用户调整规划，不擅自写完结，也不反复制造无意义的新危机拖延。

## 六、选定方向与正式细纲的关系。

选定方向作为本次生成的独立计划，包含主要事件、目标字数和本章停止位置，用于指导正文及核对选择是否落实，写前不冒充正式细纲。

批量自动采用的推荐方向与单章手动选择使用同一份计划结构和核对逻辑。正文须先按已选方向及原有大纲边界核验，再生成反向细纲，不能通过事后重写细纲来掩盖正文偏离方向或提前完结的问题。

正文完成且通过适用检查、修复和润色后，以最终保存版本生成正式细纲，至少记录实际事件顺序、主要冲突、人物行动、结果、伏笔变化和实际章末落点。未写出的方向内容不能写成已发生事实。

细纲采用现有逐章 Markdown 格式，并保存来源正文哈希及“正文反向生成”的来源信息。章名优先保留用户已定名称，创建时不得覆盖用户后来补写的细纲。

同章分轮续写或取消产生的半稿，不标记为章节完成，不生成完整章节的正式细纲。保留当前正文和已选方向，重试从原断点继续；已有的事实同步继续遵循原有证据规则。

已反向生成细纲的章节再次补写或修改后，应显示该细纲与概要是否过期；自动更新仅处理本功能生成且无人编辑的版本，用户修改过的细纲走现有差异处理流程。

## 七、写后同步与恢复。

本模式的“完成”包括正文保存、本章细纲生成、有效概要生成及记忆同步。即使全局自动同步关闭，界面也明确告知本模式包含这些步骤，后端按本模式完成必要处理，不修改全局开关。

概要和记忆都依据最终保存正文，而不是候选方向或反向细纲；继续核对人物、地点、物品、伏笔、剧情点、角色状态和设定变更的证据。

只有大纲的首次写作同样执行完整写后流程，新记忆从本章正文开始建立。不为缺失的前章补建虚构的正文、细纲、概要或事实记忆，不把本章人物的推测、转述自动登记成此前已证实的事件。

正文保存成功后，任何后处理失败都保留正文，准确标出失败步骤，并支持“补生成细纲”“补跑记忆同步”。恢复时复用已成功的同版本结果，不重新生成正文。

生成方向时记录来源版本及资料缺失状态；采用方向前核对前文、大纲和目标章是否改变，包括原先缺失的正文或细纲后来被补入，变化后重新生成或重新核对。生成细纲及提交记忆时再次校验正文版本与任务身份，避免旧任务覆盖作者新内容。

使用分步检查点实现可恢复提交，不假设正文、细纲和多个记忆文件能够一次原子写入。程序重启后应能找到待完成步骤。

批量检查点同时保存候选方向、推荐项、实际采用项、上下文版本和各写后步骤状态。恢复时先完成当前章的必要处理，再推进后章，不因重复点击继续而重复写章、创建细纲或提交同一份记忆。

## 八、改动范围与实施顺序。

1. 后端基础：抽取缺纲判断、完整大纲及可选事实上下文读取，支持只有大纲的输入，新增五方向、唯一推荐项、推荐理由的结构化生成与校验，记录候选版本标识。
2. 写作接入：让正文生成器显式接收已选方向及完结授权，保留现有事实、章节边界和版本检查。
3. 写后处理：新增基于正文的细纲创建服务，串接概要和记忆同步，接入检查点与补跑。
4. 界面接入：新增方向选择组件，标记并默认选中推荐方向，连接章节编辑器及流程面板，补充加载、取消、过期与失败状态。
5. 通道接入：更新 `src/shared/types.ts`、`src/main/ipc/write.ts` 和 `src/preload/api.ts`，核查完整 Web 的传输与取消通道。
6. 批量接入：调整“一键十章”的逐章编排，缺纲时自动采用推荐方向，接入写后反向细纲、同步完成后再推进及断点恢复；已有细纲章节保持按纲生成。
7. 兼容回归：首版覆盖桌面与共用章节编辑器的完整 Web，包括手机浏览器，并覆盖“一键十章”；独立手机配对页的候选采用机制需单独接入，避免预览阶段写细纲或记忆。

## 九、验收重点。

- 缺少目标章细纲时必出五个可选方向，有细纲时常规续写正常运行；空模板和仅有章名的情况判定正确。
- 五个方向中恰好一个推荐项，推荐理由与本书内容一致；推荐标识缺失、重复、指向不存在候选或违反约束时不继续写作。
- 单章默认选中推荐方向但允许改选；“一键十章”缺纲时自动采用推荐项，已有细纲时按原细纲写作，混合批次无需逐章确认。
- 仅有大纲时也能启动“一键十章”；后章方向使用前章最终正文及成功同步的最新记忆，不预先固定十章走向。
- 每章正文、适用的细纲创建或同步、概要和记忆处理完成后才推进后章；中断或失败后补跑当前章，不重复写正文，停止任务后不再启动后章。
- 大纲存在而上一章正文缺失时仍能生成五个方向；没有任何正文、细纲和记忆时，也能从选择方向走到正文、反向细纲和记忆同步完成。
- 有上一章正文时，五个方向可核对到实际承接点；只有大纲时可核对到目标阶段、全书主线与后续边界，不能虚构上一章实际结尾。
- 第一章、跳到指定章写作、只有旧概要但原文缺失等情况正确区分事实与计划，不要求补写缺失的历史章节。
- 选择、编辑、重新生成、取消和章内断点续写可用，未选方向不进入正文或记忆。
- 未获明确授权时，有纲及无纲续写均不写全书完结，包括“一键十章”的推荐方向及批次最后一章；普通章末收束不误判，明确授权最终章时允许正常完成。
- 反向细纲与最终正文一致，未发生事件不入纲、不入记忆；概要与记忆来源哈希一致。
- 细纲或同步失败后，正文保留，可跨重启补跑；已完成步骤不重复生成正文或重复写入同一事实。
- 生成期间前文、大纲、细纲或正文被修改时，旧结果不会覆盖新版本。
- 验证关键服务与交互分支，并运行相应回归、类型检查及构建；真实模型抽样核验方向差异、承接质量与禁止主动完结的实际效果。

## 十、实施与验证记录。

已接入桌面和完整 Web 共用的章节编辑器：无有效细纲时展示五个方向、唯一推荐及推荐理由，支持改选、补充调整、重新生成与取消。有有效细纲时沿用原有流程。“一键十章”逐章生成并采用推荐项，依据最终正文创建带原文证据的细纲，完成概要和记忆同步后才推进下一章。

候选及采用记录保存在项目的 `.cache/chapter-directions` 中，与事实记忆分开。上下文变化会使旧候选失效，自动生成的细纲包含正文哈希和任务标识，作者修改过的版本不会被自动覆盖。细纲或记忆失败后保留正文，批次恢复只补跑后处理。
