# 大神持笔正文写作使用指南

这份指南介绍如何在「大神持笔 桌面版」中写出一章正文、修改已有内容，以及连续生成多章。适用于当前项目代码中的功能，整理日期为 2026 年 10 月 1 日。

推荐先用单章流程试写并确定文风，再启动批量写作。日常操作顺序是：准备细纲 → 设置写作要求 → 续写 → 检查和改稿 → 正式保存 → 核对记忆同步。

## 1. 第一次使用前的准备

### 配置模型服务

1. 打开「设置 → 模型服务」。
2. 配置要使用的服务商、模型及对应的连接或认证信息；采用 API 通道时填写相应的 API Key 和服务地址。
3. 使用服务商卡片上的「测试」或「测试当前连通」检查配置。
4. 核对功能模型路由，让正文生成使用预期的服务商和模型。正文编辑页顶部也可以查看和切换「正文模型」。

不同模型通道提供的调节项不同，可能是温度、思考强度或模型档位。初次使用先保留当前配置，观察实际成稿后再调整。

### 准备小说资料

打开要写的小说项目，准备以下资料：

| 资料 | 建议填写的内容 | 用途 |
| --- | --- | --- |
| 设定 | 核心设定、人物身份、能力规则、重要关系 | 给写作提供背景和约束 |
| 大纲 | 主线、卷结构、章节推进方向 | 保持全书方向一致 |
| 本章细纲 | 核心事件、场景推进、人物行动、伏笔安排、章末落点、字数预估 | 指导本章具体写什么 |
| 已写正文与记忆 | 前章实际发生的事件、人物当前状态、未解决的问题 | 接续剧情，避免把计划当成事实 |

在「章节」页可以用「+ 新章」创建章节。已有细纲时打开相应章节；没有细纲时，可通过本章细纲区域或大纲页的相关功能生成、导入或完善细纲。大纲页提供「AI 批量生成细纲」。

**建议先补齐本章细纲。** 没有细纲时，本章长期写作要求无法配置，生成会缺少明确的章节任务，连续模式也无法完成细纲对照。

细纲记录的是计划，记忆和追踪记录的是已经发生的事实。例如，「计划第 20 章揭晓身份」不能提前写成角色已经知道身份。

## 2. 快速完成第一章

1. 在「章节」页打开目标章节。
2. 查看左侧「本章细纲」，确认核心事件、章末落点和字数预估。
3. 查看「本章登场人物」与「本章伏笔提醒」，核对出场、铺设和回收安排。
4. 在「长期写作要求」中点「编辑」，选择模板或自己填写，再保存要求。
5. 核对顶部的正文模型；如果有文风档案，可以选择项目默认文风或指定文风。
6. 点击「续写」。需要额外要求时，填写临时要求并点「带临时要求续写」；否则点「按长期要求续写」。
7. 等待生成完成，在自动打开的「流程面板」中查看质检、自检和写后同步结果，阅读正文并修正问题。
8. 点击顶部「保存」或按 `Ctrl+S` 正式保存正文。改稿后再核对、补跑记忆同步，然后写下一章。

空白章节可以从零生成；已有正文时，「续写」会接在当前正文后面。要修改已经写出的段落，使用「按要求重写」更合适。

## 3. 写作要求怎么填写

### 本章长期写作要求

这里的「长期」指同一章后续续写时持续采用的要求，并不代表自动应用到全书所有章节。配置需要本章已有细纲。

点击「编辑」后，可以选模板并补充自己的要求，也可以选择「仅自己填写」。模板可在「设置 → 写作要求」中管理。

适合填写稳定的写法、视角和边界。例如：

```text
本章以林远的有限视角叙述，不写他不知道的内情。
通过对话和行动推进争执，主角用证据改变局面。
保留人物犹豫和误判，不让配角只负责夸赞主角。
身份线索只铺设到读者能察觉异常，不在本章揭晓答案。
章末停在来人出示旧案证物的位置。
```

### 本次临时要求

点击「续写」后的弹窗提供临时要求输入框。它只影响本次续写，不会覆盖本章长期要求。

适合说明接下来这一段具体怎么写，例如：

```text
接着刚才尚未说完的台词写。先让林远核对账单，再指出日期矛盾。
让对方提出一个有道理的反驳，林远用第二份证据回应。
这次先推进到双方同意查验仓库，不要提前揭晓幕后人。
```

如果勾选「下次直接续写，不再弹出此确认框」，后续会直接启动续写。经常需要逐次补充要求时，先保留弹窗。

### 全局续写规则

「设置 → 续写规则」用于调整共用的写作规则，例如自然准确的叙述、句段节奏和对话规则。它与本章长期要求、单次临时要求是不同的配置层。

填写要求时尽量说明「谁做什么、为什么、推进到哪里、哪些信息暂不揭晓」。如果要求之间冲突，先统一内容，再生成。

## 4. 字数和多次续写

AI 的章节目标字数来自本章细纲的「字数预估」；没有填写或无法解析时，会采用默认目标，编辑页会提示。

编辑页允许手动修改显示的章目标，但界面会说明：**AI 实际仍按细纲字数写。** 如果希望改变模型生成的篇幅，应修改细纲的字数预估。

有前文时，系统会结合已写篇幅判断继续展开还是进入收尾。继续展开时本章可能仍是半成品，自检中的完成度提示应结合这个阶段理解；进入收尾也不意味着可以省略关键剧情。

字数是篇幅参考。先判断事件是否完成、人物行动是否合理、章末是否到达预定落点，再决定继续写或修改细纲。不要为了凑数反复解释同一件事。

本章已有正文会作为续写上下文使用。单章文本超过 40000 字符时，相关生成或记忆提取流程可能明确要求分章；这里的字符数与界面字数统计不是完全相同的口径。

## 5. 检查生成后的正文

「流程面板」可以通过编辑页顶部按钮展开或收起。不要只看“生成成功”，还要区分检查是否执行、是否完成，以及结果对应哪个正文版本。

| 检查或工具 | 主要用途 | 怎么处理 |
| --- | --- | --- |
| 质检 | 检查文字层面的规则和明显问题 | 定位原文，判断后修改，再重新质检 |
| 写后自检 | 核对本章约束和完成情况 | 结合半成品或完整章状态处理；必要时转成重写或临时续写要求 |
| 细纲对照 | 找出正文与细纲的差异 | 决定补写正文，或以实际正文更新细纲 |
| 深度审稿 | 用模型检查逻辑、动机等问题 | 查看原文依据；调用失败时视为检查未完成 |
| 章节概要 | 概括本章实际内容，供后续上下文使用 | 正文改动后重新生成，避免使用过期概要 |

通过顶部「⋯ → 重新质检」或 `Ctrl+Shift+A` 可以重新检查。自动深度审稿可在「设置 → 审稿规则」配置；没有执行深审，不能理解为剧情逻辑已经通过验证。

### 正文与细纲不一致时

单章模式需要作者判断差异：

- 漏写了仍然必要的事件：补写正文。
- 正文采用了更合适的细节、行动或结果：检查后用「以正文更新细纲」回写。
- 涉及核心事件、人物变化或卷结构：回写前评估后续章节是否依赖旧安排。

流程面板的推荐项不等于所有差异都可以直接接受。「无差异」也只代表本次对照没有发现差异，最终仍需阅读成稿。

## 6. 修改正文和去 AI 味

### 按要求重写

1. 点击「按要求重写」。
2. 输入修改要求，尽量限定要改的事件或段落，并说明要保留的内容。
3. 先生成修改建议，查看方案；需要时编辑建议或勾选要落实的要点。
4. 点击「确认落笔」执行重写。也可以使用界面提供的入口，跳过建议直接按要求落笔。
5. 查看重写结果、自动复检和要点落实情况。
6. 正式保存正文，并核对记忆同步结果。

可直接参考这份要求：

```text
修改仓库对峙这一段：守卫阻拦是因为交接手续未完成，不能只因为看不起主角。
主角先核对交接单，再指出签名与时间的矛盾。
保留进入仓库的结局和章末证物，不新增幕后人物，不改动其他场景。
```

落笔后不会自动完成正式保存。`Ctrl+Z` 可撤销当前改写；已有保存版本可以通过「历史版本」预览和恢复。

### 追问

「追问」用于让 AI 回答当前正文的问题，例如「人物为什么突然改变立场」「这段有没有跨章矛盾」。回答本身不会改正文，需要修改时再使用「按要求重写」。

### 去 AI 味

点击「去 AI 味」扫描文字问题，按界面选项进行润色，查看改动对照后再应用。应用后阅读上下文，确认人物语气和事件事实仍然准确，再保存和核对同步。

长文润色中途停止时，已完成的分块结果可能保留供确认。以面板实际返回的内容和日志为准，确认应用前检查结果。

## 7. 保存、草稿和历史版本

应用中的自动草稿、正式正文和历史版本用途不同。

| 类型 | 作用 | 需要做什么 |
| --- | --- | --- |
| 自动草稿 | 编辑后延迟备份，重新打开章节时可提示恢复 | 意外中断后查看恢复提示；仍需正式保存 |
| 正式正文 | 写入项目的正文 Markdown 文件 | 点击顶部「保存」或按 `Ctrl+S` |
| 历史版本 | 保留最近 5 个正文历史版本，供预览和恢复 | 大改前先保存；恢复后检查记忆是否也需要更新 |

正式正文位于项目目录的 `正文/` 下，常见文件名是 `第001章 标题.md`。历史版本位于 `正文/.versions/` 下。

单章续写和重写完成后应主动正式保存。批量生成会逐章保存正文，再处理后续检查。两种流程的保存行为不要混用。

正文撤销与「撤销同步」也是两件事：前者恢复文字，后者撤销最近一次可撤销的自动记忆或设定同步。恢复或改写正文后，需要重新检查派生记忆。

## 8. 记忆与设定同步

生成下一章时，系统会结合细纲、设定、人物和相关历史正文等资料构造上下文。写完后同步记忆，是为了让下一章读取到实际发生的新变化。

在「设置 → 写作节奏」中，可以设置「续写完成后自动后处理」：

| 选项 | 行为 |
| --- | --- |
| 仅记忆与设定 | 默认选项，自动处理记忆和设定同步 |
| 完整 | 记忆同步后，继续运行细纲对照、节奏和图解等后处理 |
| 关闭 | 需要在流程面板手动处理 |

「设定随书进化」另外提供高置信自动应用、全部手动确认、关闭三种策略。它用于世界观、势力等设定增量，不自动修改题材定位。

同步时，提取出的条目还要核对正文证据。**提取成功不等于所有条目已经写入。** 查看已应用数量、待核对内容和失败提示。

- 显示「记忆待核对，尚未生效」：检查对应原文和候选条目，核对后应用，或修文后重新同步。
- 显示同步失败或部分失败：使用「补跑同步」等入口重试，保留已经成功的正文。
- 手动编辑、重写旧章或恢复历史版本：正式保存后，基于新正文重新同步该章。
- 查看批量遗留候选：在章节页使用「记忆待核对」入口，必要时「重跑本章记忆同步」。

流程面板的「一键同步」会触发细纲对照、记忆提取、节奏评估、图解生成和章节概要。这比单独补跑记忆同步包含更多工作，按实际需要使用。

## 9. 批量续写和一键写 10 章

### 选择批量方式

在「章节」页点击「批量续写」或「一键写 10 章」。

- 「批量续写」提供逐章暂停确认的方式，也可以勾选连续写作。
- 「一键写 10 章」会预选下一段未写章节，并开启连续模式。若范围后面已有正文，默认范围会缩短。
- 可填写起始章号、结束章号，或用 1、3、5、10、20 章快捷按钮选择数量；单批最多 100 章。
- 所选范围已有正文时，需要缩小范围。批量生成不会覆盖已有正文；重写已有章节应打开该章操作。

第一次批量写作，建议先选 1—3 章并逐章确认，检查文风和同步结果。

### 开始批量续写

1. 确认所选章节的细纲、人物和关键设定已准备好。
2. 核对起止章号，处理已有正文提示。
3. 决定是否勾选「连续写作，以正文为准更新细纲和记忆」。
4. 如需按章节节奏动态调整生成强度，再启用相应选项；该选项默认关闭，支持程度取决于模型通道。
5. 点击「开始批量续写」；开启连续模式时，按钮显示为「一键写 N 章」。
6. 查看当前进度、逐章小结和记忆待核对项。逐章暂停时，阅读并处理本章，再继续。

### 连续模式会改变细纲

连续模式以实际正文为准，逐章执行：

1. 生成并保存正文。
2. 对照细纲，将差异按正文回写到本章细纲，包括漏写、严重差异和卷级变化。
3. 校准同卷后续未写章节的允许字段。
4. 对更新后的细纲重跑自检。
5. 按正文同步记忆和设定，再写下一章。

该模式不受普通自动记忆开关影响。剩余的正文自检提示会记录在逐章小结里；细纲缺失、对照或回写未完成、同步失败等问题会使流程暂停。

**连续模式可能接受偏离原计划的正文，并据此改动后续细纲。** 如果需要严格保留原定事件或逐章判断偏离，使用逐章暂停确认方式更合适。连续批次完成后仍应阅读正文与逐章小结。

### 停止和恢复

- 点击「停止」会取消当前模型请求和后续处理；已保存的正文保留。
- 未结束的批次会保留本机恢复记录，重新打开批量弹窗可继续。
- 正文已保存但检查未完成：使用界面的重试检查入口，复用已保存正文补跑检查，不必重新生成。
- 正文生成或保存失败：根据提示重试。生成完成但保存失败时，应用会尝试写出恢复稿，并在错误信息里给出路径；通常位于项目的 `.cache/batch-drafts/`。
- 本批开始后范围会固定。需要重新选范围时，先点「结束本批」；此操作清除本批恢复记录，保留已保存正文。
- 切换页面或项目会中止本次运行，之后通过批量弹窗核对并恢复进度。

单章编辑页的「停止生成」会恢复生成前的正文；批量停止则保留已经逐章保存的正文。恢复时根据所在流程判断。

## 10. 常见问题

| 遇到的情况 | 建议操作 |
| --- | --- |
| 提示模型未配置或认证失败 | 到「设置 → 模型服务」核对服务地址、认证和模型路由，重新测试连接 |
| 正文里缺少关键事件 | 查看本章细纲和自检，补写缺失事件，或用按要求重写修正 |
| 目标字数改了，生成篇幅仍不对 | 修改细纲的字数预估；编辑页手动目标不改变 AI 的实际细纲目标 |
| 生成超时、输出为空或返回流程说明 | 查看错误提示；核对模型和网络后重试，必要时减少单次任务篇幅 |
| 检查显示未完成 | 重新运行相应检查，不把空结果当作通过 |
| 正文已生成，但记忆同步失败 | 先正式保存正文，再补跑同步；不必仅为同步失败重新生成正文 |
| 显示记忆待核对 | 阅读候选条目的原文依据，核对后应用，或修文重新同步 |
| 改稿后概要过期 | 重新生成概要并核对同步；后续续写不会使用失效的旧概要 |
| 重新打开后出现未保存草稿 | 查看草稿恢复提示，恢复后核对内容，再正式保存 |
| 批量范围包含已有正文 | 缩小范围；已有章需要修改时打开该章重写 |
| 批量暂停，但本章文件已存在 | 优先使用重试检查入口，避免重复生成已经保存的正文 |
| 历史版本恢复后人物状态不一致 | 以恢复后的正文重新同步，并检查受影响的后续情节 |

## 11. 交稿前检查

- 本章关键事件已经落到正文里，人物动机、位置和知情范围合理。
- 伏笔的铺设、强化、部分揭示与完整回收没有混淆。
- 章末到达合适的落点，没有为凑字数重复叙述。
- 关键质检、自检或审稿提示已阅读；未完成的检查已明确处理。
- 最新正文已经正式保存，概要和记忆同步对应当前版本。
- 批量连续模式下，已查看改动后的细纲和逐章小结。

交稿时可在「章节」页使用「导出全书 TXT」导出已保存的全书正文。
