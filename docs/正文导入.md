# 正文导入

桌面版书架顶部点击“导入正文”，可多选 TXT、Markdown 文件，选择正文文件夹，或直接粘贴文件夹路径。文件夹内的分卷子目录也会读取；设定、大纲、细纲等项目资料目录及链接不作为正文扫描。

填写书名，检查预览，再点击导入。默认识别 UTF-8 和带 BOM 的 UTF-16；旧版中文 TXT 如果解码失败，可以选择 GB18030 / GBK 后重新读取。一次最多 3000 个文本文件，总大小不超过 64 MB。DOCX、PDF 等格式暂不支持，检查结果会列出未处理文件。

每章可以单独一个文件，也可以在一个文件内按明确的“第 N 章”标题拆分。支持阿拉伯数字、中文数字，按数值章号排序。没有内部章标题的单章文件，可以使用 `第001章_章名.txt` 或 `001_章名.md` 等文件名。无法明确识别章号、存在未归属前言、文件名与正文标题冲突、分卷重新编号等情况会列入问题，不猜测、不改写。

- 相同章号、相同原文只导入一次，列明重复来源。
- 相同章号的不同版本、不同章号的相同正文会暂缓导入。
- 缺章检查限定在识别到的最小章号至最大章号之间，不补写、不改号。
- 有缺章或未处理问题时，可明确勾选只导入可用章节，其他来源保留待处理。

导入始终创建一本新小说；保存位置使用应用设置中的小说目录。同名文件夹存在时要求修改书名，不合并或覆盖旧项目。原文件保留在原处，归档后的正文保留原有文字、标点、缩进、段落和换行，仅转换为 UTF-8 Markdown 文件。保存的是本次预览时读取的内容；预览后又修改原稿时，应重新读取再导入。

新项目只创建逐章正文和用于项目、章节识别的最小 `大纲/大纲.md`。不调用 AI，不生成新剧情、细纲、人物卡或设定。章节表中的节奏字段为“待评估”，解析为占位值 0，不代表节奏评分。保存后自动登记书架，可直接打开章节。

开发验证：

```powershell
npx vitest run tests/prose-import.test.ts tests/prose-import-ipc.test.ts
npm run build
node scripts/prose-import-ui-smoke.mjs
```

界面冒烟测试使用隔离的临时用户目录和模拟 API，不读取或修改真实小说库。
