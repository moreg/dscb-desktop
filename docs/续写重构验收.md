# 续写重构验收

## 提炼后的需求

1. 同一套创作语义覆盖新章、章内续写、授权重写和批量。生成、提出候选、保存、记忆提交各有独立边界。
2. 作者本次的明确要求在操作范围内优先。作品规则、选定文风和既有正文继续参与生成，细纲负责计划和停止位置。默认提示按人物处境、信息来源、行动因果和整场交流指导表达。
3. 同章已写前部逐字保留，按实际断点续写。历史事实依据续写时间点之前的有效正文和带来源的记忆，猜测、计划和旧稿分开处理。
4. 润色仅处理获准范围，保留事件、道具、数量、说话归属、人物知情和结尾落点。冲突、取消或核对失败时保留可恢复稿件，并按原有验收机制暂停交稿或记忆提交。

## 入口和数据流

| 入口 | 当前链路 | 交付边界 |
| --- | --- | --- |
| 桌面、完整 Web（包括手机浏览器） | 章节编辑器 → preload 或 Web IPC 桥接 → `write:generateChapter` → `deliverChapter` → `generateChapterStream`。 | 后端返回带保存回执的整章稿，编辑器直接采用同一份正文。章内续写仅格式化新增部分。 |
| 按要求重写 | `write:planAdjustChapter` 生成供勾选的方案，`write:adjustChapter` 按直接要求或已确认方案生成完整修订稿。 | 重写按原稿和授权范围执行，沿用版本化保存与写后核对。 |
| 手机局域网配对页 | 单章 AI 路由 → `generateChapterStream` 或 `adjustChapterStream` 的候选模式 → 手机页。 | 生成期间保留事实核对与适用的润色。采用时校验本地基线，再走原有带版本校验的正文保存接口。断开请求会取消候选生成。 |
| 桌面、Web 和手机批量 | 各入口 → `generateChaptersBatch` → 单章流程 → 同一正文生成器。 | 沿用批量恢复、写后核对和记忆提交。必需核对或记忆提交未完成时暂停后章推进。 |

重构前，重写和拟定修改方案沿用了从零写章的系统提示，手机预览会在服务端提前落盘，桌面编辑器也会在接收最终续写稿时再次格式化整章。现在按操作组装提示，手机明确区分预览与采用，桌面采用后端已确认的正文。生成用细纲与保存前的正文版本分别校验，避免准备上下文期间的改动被旧请求覆盖。

## 提示与配置

- 系统提示保留题材语感、文风档案、作者自定义规则和叙事保真约束。生成省去内置逐词替换表及部分与专门核验重复的条款，允许有用途的正常问答、合作、玩笑、心理和转述。
- 用户提示继续传递设定、角色、历史原文和概要、细纲、后章边界、字数及同章前部。临时要求在上下文后注入一次。授权重写使用完整原稿，输入超出限制时明确失败。
- 配置和作品存储沿用原格式，旧项目无需迁移。原有正负提示、旧规则兼容、文风档案、自动润色设置和正文历史仍由原入口读取。出版章名仍走章节元数据，故事内的题头可保留。
- 回退可从独立目录启动此前的应用构建并读取现有项目。源码工作区有既有未提交修改，源码回退应按本次增量处理，保留原有工作区改动。
