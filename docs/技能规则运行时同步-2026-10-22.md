# 技能规则运行时同步

本次以 `E:\trea\技能` 的六套技能为来源，将创作和审核规则编入应用提示词。打包程序无需读取被 Git 忽略的 `.agents/skills`，也不依赖本机绝对路径。

| 技能来源 | 实际模型调用入口 | 运行时规则 |
| --- | --- | --- |
| 小说立项 | 长篇脑洞、开局定位、大纲生成 | `skill-contracts.ts`、`opening/planning-rules.ts` |
| 大纲审核 | 使用规划规则的编辑审核 | 同一规划规则中的完整性、因果、人设、命名、世界观、伏笔和证据边界 |
| 细纲生成 | `OutlineService.generateDetailed` | 规划规则、`opening/chapter-outline.ts` 的十五子节模板 |
| 细纲审核 | 规划内复核及正文细纲对照 | 设定和上游一致性、预算同源、结局唯一、到场/知情、七项表达复核 |
| 正文写作 | 整章、批量、继续推进、检查收尾 | `index.ts`、`chapter-rules.ts`、`scene-naturalness.ts` |
| 正文审核 | 单章审稿、逐项深审、对白复核及去 AI 味 | 共享规划/人物/对白规则、原有检查项和各流程原有输出协议 |

这是现有入口的规则同步，没有新增独立的大纲/细纲审核按钮。保留应用的 JSON、替换补丁和单项审核协议，不把技能的工具调用说明、文件操作流程或完整报告模板塞进模型正文输出。

正文冲突以 `正文写作/references/续写写作规则.md` 及 `细纲生成/references/正文规则衔接.md` 为准：

- 整章直接对白目标 70%，排除标点与空白后按字数观察；续写合并前部，多章逐章观察，细纲及短片段不单独验收。不设置比例自动否决或为占比反复改稿，事实与范围保真仍优先。
- 中文句号不出现在台词引号内（包括闭合前），多句台词拆为引号完整的独立段落；问叹号保留，必要动作置于完整发言前后。
- 叙述按语意分段，不强制一句一段。自动排版同步保留叙述原有分段，避免把模型输出改回旧标准；不会自动重排已存章节，只有现有生成、编辑或格式化入口调用时生效。
- 番茄开篇规则只按平台与章节范围适用；明确的题材和节奏要求优先，上游缺口不得由续写擅造结果。
- 人物说话方式由稳定档案与当前情绪、对象、场景共同决定；创作与润色权限不同。未来计划不冒充正文事实，实际图谱值不为预测强改。

已保存设置不写回。已识别的旧内置一句一段和台词末尾句号条款在组装时迁移；未知自定义文本及停用小节保持原意。本次不读取或修改作者私人记忆，不触发付费模型实测。
